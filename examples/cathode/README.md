# Cathode — a deliberately hostile example

A retro CRT terminal design system whose native language contains no "primary", no "secondary", no light-first assumption — built to prove that an uncommon design system still compiles cleanly through the semantic catalog.

## What's weird about it

- **Its own vocabulary.** The DS speaks in `crt.ink`, `crt.tube`, `crt.glass`, `crt.scanline`, `crt.amber`, `crt.meltdown`. These live as *custom semantic tokens* — legal in the IR, carried with full provenance.
- **Dark is native.** The terminal look is the default mode; "light" is a paper-printout mode. (`modes.color-scheme.default: "dark"`.)
- **The brand color is the text color.** Phosphor green is simultaneously `primary` and `text` — and it flips polarity across modes (glowing green on black ↔ ink green on paper).
- **Radius 0, monospace as the "sans" font.**

## The layered layout (the actual lesson)

Three token files, every one of them pure, tool-ingestible DTCG — no transtyle syntax anywhere except the config manifest ([ADR-0009](../../docs/adr/0009-token-layering.md)):

| File | Role | Owner |
|---|---|---|
| `tokens/cathode.tokens.json` | Source of truth: option palette + the `crt.*` vocabulary, native (dark) values | the design system |
| `tokens/cathode.light.tokens.json` | Paper-mode values for the vocabulary — its *mode assignment lives in the config*, not the file | the design system |
| `tokens/transtyle.bindings.tokens.json` | One-line aliases binding catalog slots to the vocabulary (`primary.base = {crt.ink}`) | the platform team |

```jsonc
// transtyle.config.json — the only transtyle-specific file
"tokens": [
  "tokens/cathode.tokens.json",
  { "files": "tokens/cathode.light.tokens.json", "mode": { "color-scheme": "light" } },
  "tokens/transtyle.bindings.tokens.json"
]
```

The design system thinks in its own language and its files can be regenerated by design tooling without losing anything; the catalog binding is transtyle knowledge *about* Cathode, versioned separately. Mode variation lives on the vocabulary tokens (`crt.ink` has a paper form), so every catalog binding stays a pure alias. (Restructuring this example from inline `$extensions` — still supported, see Acme — to this layout produced byte-identical compiled output.)

## Build it

```bash
npx transtyle build          # → dist/shadcn/globals.transtyle.css + dist/echarts/theme.*.json
```

**See it rendered:** [demo/](demo/) contains the same seven npm demo projects as Acme's (file-identical except `ds.config` — that's the point), terminal-dark by default: a phosphor-green Bootstrap, CRT shadcn/ui, daisyUI, and `@radix-ui/themes` (green preset override), a green-anchored ECharts dashboard, a Storybook whose chrome boots dark, and the plain CSS-variables page. From the repo root:

```bash
npm run dev -w cathode-demo-bootstrap   # port 4201   (also: -daisyui 4202, -shadcn 4203, -echarts 4204, -storybook 6201, -css-variables 4205, -radix 4206)
```

Things to observe in the output:

- `:root` is **paper mode**, `.dark` is the **terminal** — shadcn's structure is light-first, and the exporter binds mode *names*, not the DS's default flag. (This example found that bug; see the mode-polarity rule in `docs/architecture/ir.md`.)
- `--primary-foreground` in dark mode is near-black — contrast-pick against glowing green, derived, correct.
- Everything the DS didn't author (secondary, subtle tints, hover states, the chart palette) derives green-anchored: the data-viz palette starts at phosphor and rotates from there. Open `dist/echarts/theme.cathode-terminal-dark.json` — phosphor-green series on tube-black, a dashboard from 1983.
- `--radius: 0rem` makes shadcn's `--radius-sm: calc(var(--radius) - 4px)` negative; browsers treat negative radii as invalid and render 0 — the correct brutalist result, by accident of CSS. A future `check` rule could warn here.
- Amusing: `success` derives to hue 150 — nearly phosphor green. On a CRT, everything is success.

## Honest limitations this example exposes

Derived `info` is blue — jarring on a monochrome terminal aesthetic. Derivation guarantees *coherence*, not *art direction*: a real Cathode maintainer would author `info: {crt.amber}` (one line). That boundary — deterministic rules produce defensible defaults, humans own taste — is by design (ADR-0005).
