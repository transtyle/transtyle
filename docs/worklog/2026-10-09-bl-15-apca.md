# APCA as a selectable contrast standard (BL-15)

Issue [#92](https://github.com/transtyle/transtyle/issues/92), backlog
[BL-15](../backlog.md#bl-15). `check.contrast.standard` accepted WCAG 2.1 AA and
AAA; WCAG 2.1's ratio misjudges light text on dark backgrounds, the case dark
modes and Cathode live in.

## What was built

- `packages/core/src/contrast.js`: one object per standard (measure, magnitude,
  level by use, format, `diff` tolerance). `runChecks`, `contrastRegressions`
  and DERIVE's on-color picks all take it.
- `check.contrast.standard: "apca"`, through the `apca-w3` package (0.1.9, base
  algorithm 0.0.98G-4g) as an optional peer dependency of core, loaded from the
  project only when selected ([ADR-0013](../adr/0013-apca-optional-peer.md)).
  Missing, it is `TST1013` (appended). The repo pins it as a root dev dependency.
- Levels from APCA's Bronze simple mode: Lc 75 for `text.base` (body), Lc 60 for
  `text.muted` and the on-colors. `|Lc|` is compared, the sign printed.
- `derivation.contrast` (`wcag21` | `apca`, default: the check standard's
  family): the on-solid pick, the on-tint and role-text walks (target Lc 60),
  the `text.base` default and `swap-neutrals`' polarity test use it (its
  `TST1206` hint prints the measurement in the method's unit); non-default rule
  names carry `apca`.
- On-color checks moved from `derive.js` into `checks.js`'s shared pair list
  (`contrastPairs`: the four surface pairs plus `on-solid`/`on-tint` for every
  built-in and archetyped role), measured on resolved values.
- `check --json` gains `contrast: { standard, algorithm }`; `diff` prints Lc
  under APCA and `--json` rows carry `unit` and `standard`; `worsened` needs a
  drop of more than 1 Lc (0.05 of a ratio under WCAG).
- Printed values keep the round-toward-zero rule of #176 for both units.

## Findings

- Two defects in the old on-color checks, independent of APCA: they were
  hard-coded at 4.5:1, so `wcag21-aaa` never applied to them; and the on-solid
  warning measured the white/near-black _pick_, not the resolved value, so an
  authored `on-solid` was never checked. Both fixed by the move; neither changes
  any example's output (no example authors an on-color, all four stay clean
  under AA).
- The old on-color warnings ran per mode combination (`light+compact`); they now
  run per primary mode value, like the surface pairs. Color slots don't vary by
  a non-color dimension in any example, so no warning was lost.
- Measured on the four examples with `check.contrast.standard: "apca"`: with
  APCA picks, Cathode and Acme each keep 2 warnings (their dark `text.muted`:
  Cathode Lc -43 and -42.7, Acme Lc -49.8 and -48.6) and every on-color passes;
  with WCAG picks kept (`derivation.contrast: "wcag21"`), Cathode has 16 and Acme
  15, all but the muted-text pairs on on-colors the compiler derived. That is
  why derivation follows the check standard by default.
- The refinement on #92 quoted Cathode's dark muted text at Lc -42.9 / -42.5.
  apca-w3 on the emitted hex (`#50a252` on `#040904` / `#081209`) gives
  -43.09 / -42.73, which is what Transtyle prints: Lc is measured on the 8-bit
  hex a target ships, so a user checking the shipped colors in any APCA tool
  gets the same number. The earlier figures came from unrounded sRGB.
- `check:color` reproduces apca-w3 0.1.9's eight test vectors exactly
  (`deepEqual` on the float).

## Deviations

- The issue's first draft mapped `on-solid` to "large/UI" and `border` to
  "non-text"; APCA's Bronze mode has no non-text level and no border pair is
  checked under WCAG either, so borders stay out (as the refinement concluded).
- The issue proposed a port in `color.js`; the apca-w3 licence doesn't allow one
  under MIT, so it is a peer package instead (ADR-0013).
