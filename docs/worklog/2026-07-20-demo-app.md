# 2026-07-20 — Demo app: the same fake app, once per target

Shipped the demo-app half of backlog B2: [docs/specs/demo-app.md](../specs/demo-app.md) (seven required sections, implementation rules) and [examples/demo-app/](../../examples/demo-app/) (static pages, no build step, framework runtimes from pinned CDNs).

## What exists

- `index.html` — hub; DS picker (Acme/Cathode) × mode, all targets in side-by-side iframes.
- `bootstrap.html` / `daisyui.html` / `shadcn.html` — "Nimbus Console" (header, buttons, form, card, table, modal, ECharts chart) in each framework's idiom, themed only by compiled output; per-page DS switcher + mode toggle wired to each target's own mode mechanism.
- `build-themes.mjs` — mechanical converter for artifacts that aren't browser-loadable: daisyUI `@plugin` blocks → `[data-theme]` rulesets; shadcn `@theme inline` font/radius lines → `:root`. Output committed under `themes/`; rerun after `transtyle build`.

## Decisions & findings

1. **Two compiled artifacts aren't browser CSS.** The daisyUI exporter emits Tailwind-build input, and the shadcn exporter parks fonts/radius inside `@theme inline` (dropped by browsers as an unknown at-rule). Fine for their real consumers, but any "render the theme without a bundler" scenario (this demo, the future `transtyle preview`) needs the conversion step. Worth remembering when the preview site is designed — Phase 2 may want exporters to optionally emit a plain-CSS flavor.
2. **Bootstrap column doubles as an F13 exhibit.** The acceptance fixture's CSS-variable path rethemes the token tier only; `.btn-primary` stays stock blue on the page, correctly labeled. When the real Sass-path exporter ships, this page becomes its before/after.
3. **shadcn is rendered as its token contract** (hand CSS following the component recipes), not as Radix components — labeled on the page. Good enough for eyeballing color/radius/type; not a behavior test.
4. **Cathode × Bootstrap renders an honest empty state** (no compiled artifact exists), per the B1 editorial policy.
