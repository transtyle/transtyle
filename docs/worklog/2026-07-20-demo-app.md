# 2026-07-20 — Demo projects, and the two exporters they forced

Shipped backlog B2's demo half as **real npm projects** ([docs/specs/demo-app.md](../specs/demo-app.md)), and pulled the **Bootstrap** and **Storybook** exporters forward from Phase 1 to make "demos consume only `dist/`" true for every target.

## Arc of the day

1. First cut: static CDN pages with a DS switcher (`examples/demo-app/`), then per-example static pages. Maintainer direction: demos must be **individual npm projects** with each target's real configuration and real components, consuming the transtyle-built `dist/` files.
2. That requirement exposed the honest gap: Bootstrap and Storybook had no `dist/` (exporters specced only, Acme-only `expected/` fixtures). Decision (maintainer-approved): implement both exporters now; the Phase 0 fixtures become their acceptance tests.
3. Exporters shipped, fixture-verified, then ten demo projects (5 targets × 2 examples) replaced every static page.

## Exporters

- **@transtyle/exporter-bootstrap** — Sass path (`_variables.transtyle.scss` before Bootstrap, `_maps.transtyle.scss` replacing its sRGB tint/shade derivations) + CSS-variable path (`bootstrap-theme.css`, documented F13 fidelity gap). All 214 fixture keys match value-exactly. The exporter conventions the fixtures implied were recovered _numerically_ (probe scripts against the engine): `$light`/`$dark` pseudo-roles (F12), `border-subtle = mix(role.base, surface, 0.70)` (F10), the `$dark` border at `mix(neutral.contrast, surface, 0.55)`, link←ring dark asymmetry (F13), scrim shadow ramps (F2).
- **@transtyle/exporter-storybook** — `theme.transtyle.ts` (light+dark ThemeVars, hex — polished can't parse oklch), `manager.transtyle.ts` (chrome wears the DS-native mode: Acme light, Cathode dark), `preview.transtyle.ts` (sibling stylesheet imports + one decorator driving every sibling's mode encoding + Scheme toolbar + DS backgrounds). All 52 fixture ThemeVars keys match. Composition uses a new `ctx.siblings` manifest (name/exporter/output per configured target) — artifact paths only, never resolutions.
- **Core:** `ctx.mix` exposed; **F8 radius scale** (`sm/lg/xl/full` from `md`) moved from hand-derived fixture values into `derive.js` — the rule pack now owns it.

## Demo projects (per example: `demo/{bootstrap,shadcn,daisyui,echarts,storybook}`)

Same fake page ("Nimbus Console") in real Bootstrap (Sass build), real shadcn/ui (React + vendored registry components + Radix), real daisyUI (Tailwind pipeline consuming the `@plugin` blocks natively — v0's conversion hack died here); "Nimbus Analytics" (a chart dashboard whose page shell reads its colors from the theme JSON) for ECharts; a minimal Storybook wired to the generated manager/preview fragments. Maintainer correction applied same day: the Storybook demo's exhibit is Storybook's **own chrome**, not stories — it now ships a single explanatory text story (plus one text arg so the Controls panel shows a themed input) and zero extra toolchain; the component/token stories and their Tailwind machinery were removed. That surfaced an exporter improvement: the generated preview decorator now lets the canvas wear the DS background/foreground via the sibling shadcn variables (F18), fixing dark-native canvases that previously sat on Storybook's stock white. All verified running (screenshots in-session): Acme's `.btn-primary` is finally compiled-from-theme `#026fd7` (the Sass path reaching what F13 said CSS vars can't), and Cathode produces a phosphor-green Bootstrap and a terminal-dark Storybook chrome that never existed before today.
