# Worklog — R3: real JSON schemas + strict config/options validation

**Task:** Phase A, R3 (execution-2026-h2.md); closes audit A7 and the options half of A8.

## What shipped
- **Zero-dep validator** (`packages/core/src/schema/validate.js`) — a small JSON Schema *subset* walker (type/enum/const/required/properties/additionalProperties/items/minItems/anyOf). No ajv; core stays zero-dependency by policy.
- **Schemas as single source of truth** (`packages/core/src/schema/{config,report}.schema.js`) — the same objects drive the runtime validator *and* the published files, so they can't diverge.
- **Published schemas** (`website/public/schemas/{config,report}/v0.json`, generated by `scripts/gen-schemas.mjs`) — served at the exact `$id` URL configs already reference (`https://transtyle.dev/schemas/config/v0.json`), so the previously-fictional `$schema` URLs (A7) become real once the site deploys (R5). Confirmed the files land in `website/dist/schemas/`.
- **Load-time validation** (`compile()`): config validated against the schema — unknown/mistyped keys are `TST1010` errors, not silently ignored (A8); each target's `options` validated against the selected exporter's `optionsSchema` — `TST1011`. Exporters with options now declare `optionsSchema` (shadcn `era`, storybook `previewTargets`/`remBase`/`brand`, css-variables `prefix`/`darkSelector`/`dimensionSelectors`, daisyui `era`); exporters with none reject any options via the strict default.
- **`check:schemas`** in `check:all`/CI: drift guard + all 4 example configs valid + 6 known-bad configs rejected + a real emitted `report.json` conforms.

## Verified end-to-end (throwaway project)
- unknown top-level key → `TST1010`; bad `era` enum → `TST1011`; options on a no-option exporter (echarts) → `TST1011`; valid config still builds clean.

## Notes / deviations
- **A8's manifest half (irSpec/pluginApi range-checking) is deliberately NOT implemented here.** Per [ADR-0011](../adr/0011-v0-freeze-readiness.md), the manifest format is unstable and its validation is part of the P1 plugin-API reconciliation; implementing it now would validate against a contract we just documented as not-yet-frozen. R3 scope is the user-facing config + options surface, which is stable. Ledger R3 line notes the split.
- **`brand` option:** the real sub-keys are `title`/`url`/`image` (not the `brandUrl`/`brandImage` a stale code comment implied) — verified against `emit` and schema'd correctly.
- Two engine-only test stubs (check-grid, check-component-tier) gained a permissive `optionsSchema` since they impersonate exporters that accept options; the strict-default behavior for real no-option exporters is unchanged and tested (echarts).
- New codes `TST1010`/`TST1011` documented in diagnostics.md (my own check-docs guard caught their absence) and the validation behavior added to configuration.md.
