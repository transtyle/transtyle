# 2026-07-20 — T8: multi-dimension modes + reserved dimensions

Per [docs/plan/catalog-revision.md](../plan/catalog-revision.md) T8. Picked up right after T7 — the last remaining plan task with no unmet dependency (T2 only).

## What shipped

- **`packages/ir/src/index.js`** — `RESERVED_MODE_DIMENSIONS` (names only, per ir.md), `comboKey(dimNames, values)` (joins one value per dimension into a compound key, e.g. `"dark+compact"`), `expandModeMatrix(dimEntries)` (the cross-product of every configured dimension's values), and `droppedDimensions(dimensionNames, expressed)` (one `dropped` coverage entry per dimension an exporter doesn't handle — a no-op when the compile has no such dimension).
- **`packages/core/src/normalize.js`** — removed the `modeDims.length > 1` throw. Every combo in the expanded matrix gets its own resolved `Map`, keyed by its compound key. Each token resolves independently per dimension (checks each dimension's override for that combo's value; last dimension to have a real override for that token wins — the plan's "rare pathological pair" case). **Back-compat is the whole point**: `modes.light` / `modes.dark` (or whatever the primary dimension's values are) become aliases into the combo where every _other_ dimension sits at its own default — exactly what pre-T8 exporter code already means by those keys. A single-dimension config (today's actual Acme/Cathode configs, before this task's own addition) degenerates to combo keys identical to the old mode names, so nothing about existing behavior changes structurally, only additively.
- **`packages/core/src/derive.js`** — the main derive loop now iterates `normalized.allCombos` (every combo), not just the primary dimension's values, so a combo that only varies on a _non-color_ dimension (e.g. `light+compact`) still gets every catalog-default scale/role/ladder filled in — otherwise `density: compact` would only ever see raw authored/aliased tokens, missing anything the engine fills in (radius, z-index, etc., though this worked example only touches `space.*`). `isDark` now reads the primary dimension's _component_ of the combo (`comboDims[combo][modeDimension] === 'dark'`), not the whole compound string. The `text.inverse` cross-mode pass was generalized the same way: it flips only the primary dimension and holds every other dimension's value fixed, so `"dark+compact"`'s inverse is `"light+compact"`, not the unrelated `"light+comfortable"`.
- **`packages/exporter-css-variables/src/index.js`** — the one exporter that expresses every dimension, not just `color-scheme` (this is deliberate — it's the "grid-complete conformance dump," so it should dump everything). For every non-primary dimension's non-default value, computes the diff against the all-defaults combo and, if anything actually differs, emits one selector block (`[data-density="compact"]` by default, `options.dimensionSelectors` to override the attribute template) containing only the differing variables — 12 lines for Acme's density example, not the full catalog again. `usage.md` documents it when present, omitted entirely when not (verified empty on Cathode, which has no second dimension).
- **Six closed-set exporters** (shadcn, bootstrap, daisyui, echarts, storybook, radix) — one identical line each: `coverage.push(...droppedDimensions(normalized.dimensionNames, ['color-scheme']))`. Each needed adding `@transtyle/ir` as a dependency (all six had zero runtime dependencies before this). This directly satisfies ir.md's stated rule ("exporters declare which mode dimensions they can express; inexpressible dimensions surface in the coverage report") for every shipped exporter, not just shadcn (the one the acceptance criteria named) — the addition was the same three lines everywhere, so doing it uniformly cost nothing extra and avoided leaving five exporters silently non-compliant with a rule the spec states generally.
- **`examples/acme/`** — the worked example. `transtyle.config.json`'s `tokens` array switched from a bare `"tokens/*.tokens.json"` glob to an explicit file list (needed so the new `acme.density-compact.tokens.json` mode-scoped layer isn't _also_ picked up as a plain, non-mode-scoped file by that glob) plus a `{ files, mode: { density: "compact" } }` entry; `modes.density` added (`comfortable|compact`, default `comfortable`). `tokens/semantic.tokens.json` gained an explicitly authored `space.*` scale (13 keys, at the exact values the engine's catalog-default formula already produced — a value-preserving change, only the provenance kind moves from `defaulted` to `authored`, which was necessary because a mode-scoped layer can only override a token that already has a base/default-mode entry; a catalog-default-only slot has no such entry to attach an override to). `tokens/acme.density-compact.tokens.json` (new) is the compact layer: the same 13 keys × 0.875, computed and rounded exactly like the engine's own `trimNum`.
- Docs: `docs/architecture/ir.md` (status banner: T8 done, "T1–T4, T6–T9"), `docs/specs/exporters/css-variables.md` + website mirror (new "Multi-dimension modes" / "Extra mode dimensions" sections), `website/src/docs/roadmap.md` (moved from Specced to Implemented; removed the stale Specced row), `ROADMAP.md` (checked off).

## Why the back-compat design was the real work

The acceptance criteria's hardest constraint was "shadcn output unchanged." Six of seven exporters, `checks.js`, the CLI, and `derivation.require` all read `normalized.modes.light` / `.dark` / `[normalized.defaultMode]` and iterate `normalized.modeValues` — none of that code should have to change for a feature it doesn't use. The design that makes this true: the primary dimension's own value names stay first-class keys in `normalized.modes`, aliased to whichever combo holds every other dimension at _its_ default. Everything downstream that only knows about `color-scheme` keeps working by construction, not by special-casing every consumer. The only places that needed to understand the _compound_ key structure at all are `derive.js`'s two loops (which must actually populate every combo) and the css-variables exporter (which chose to expose the extra dimension). This is exactly the design ir.md already sketched in T1 ("resolved per-dimension independently... Exporters receive the expanded matrix and decide the native encoding") — T8 was implementing that sentence, not inventing new architecture.
