## What shipped

- **`examples/govuk/`** — the UK government's [GOV.UK Design System](https://design-system.service.gov.uk/styles/colour/), fetched live 2026-07-21. `option.tokens.json` transcribes the published web palette + functional-colour set verbatim (hex). `semantic.tokens.json` expresses GOV.UK's own functional-colour names (`govuk.brand`, `govuk.error`, `govuk.focus`, …) as custom semantic tokens. `transtyle.bindings.tokens.json` maps eight catalog slots onto them — `primary`, `danger`, `success` map cleanly; `ring` maps onto GOV.UK's yellow focus color, the cleanest 1:1 mapping found in either adoption; `secondary`/`accent`/`warning`/`info` are deliberately left unbound (GOV.UK's functional-colour set doesn't distinguish them) and fall through to the standard derivation rules. `modes.color-scheme` declares only `"light"` — GOV.UK has no published dark theme, and forcing one would mean inventing colors GOV.UK never specified. `radius.md: 0rem` is real (GOV.UK's actual flat aesthetic), and the font binds GOV.UK's own documented fallback stack (`GDS Transport, arial, sans-serif`) since the real Transport typeface is licensed to crown services only.
- **`examples/carbon/`** — [IBM's Carbon Design System](https://carbondesignsystem.com/elements/color/tokens/), fetched live 2026-07-21 (White theme; G100/dark values are well-established Carbon v11 constants, flagged in the findings doc as not independently re-verified live for every token — see below). Carbon has real, named tokens for all four of `danger`/`success`/`warning`/`info` (its "Support" group) _and_ a real `secondary` (`$button-secondary`) — meaningfully better native role coverage than GOV.UK. `primary`, `danger`, `success`, `info`, and `ring` all bind real per-mode values via `$extensions.transtyle.modes` (Carbon's own White/G100 pair), not derived dark-mode approximations. Fonts are real, open, and load for real in the demos: IBM Plex Sans/Mono.

## A real bug this surfaced

`examples/govuk`'s first build crashed inside the Bootstrap exporter (`Cannot read properties of undefined (reading 'c')`, in `ctx.mix`). Root cause: my own bindings file had a structural mistake — `text`/`elevation`/`border`/`ring`/`link` were written as siblings of `semantic.color` instead of nested inside it (`semantic.text.base` instead of `semantic.color.text.base`), so `text.base` silently resolved as absent, which broke the F20 `neutral.text-strong` derivation, which Bootstrap's `$dark` pseudo-role reads unconditionally regardless of whether the design system declares a dark _mode_ at all. Not an engine bug — a bindings-file authoring mistake, caught immediately by the crash rather than silently producing wrong output, and fixed by renesting the file correctly (verified against Acme's actual token-tree shape before fixing, not guessed).
