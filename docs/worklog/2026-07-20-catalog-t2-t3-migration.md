# 2026-07-20 — T2 + T3: the role grid lands in the engine

Per [docs/plan/catalog-revision.md](../plan/catalog-revision.md), with the maintainer's go-ahead on "option 1" (proceed with the combined engine + migration work in one sitting).

## Deviation from the plan, logged as instructed

The plan sequenced T2 (engine) and T3 (migrate exporters/examples) as separate tasks/commits. In practice they can't be separated: the moment `derive.js` looks for `primary.solid` instead of `primary.base`, both example token files (still authoring the old names) and all five exporters (still reading the old names) break simultaneously — there is no buildable intermediate state. T2 and T3 landed together in this session, verified as one unit, and are being committed together. This is recorded here rather than silently deviating.

## What changed

- **`packages/ir/src/index.js`** — new `GRID_CELLS`, `TEXT_RUNGS`, `ELEVATION_LEVELS`, `SHADOW_LEVELS`, `Z_LADDER` constants; removed the now-obsolete `SURFACES` export.
- **`packages/core/src/derive.js`** — full rewrite implementing the catalog-revision.md T2 table: the role grid (`solid`/`tint`/`outline`/`text` × rest/hover/active/selected + on-colors) for all eight roles; the elevation ladder (`elevation.0..5.surface`, iterative `raise()`, `elevation.1..4.shadow` composed from `scrim`); the content hierarchy (`text.{strong,base,muted,subtle,disabled,inverse}`, with `text.inverse` as a cross-mode pass run after both modes resolve); `link.{base,hover,visited}`; radius family aliases; and the new catalog-default scales (`space.*`, `size.control.*`, `border-width.*`, `breakpoint.*`, `z.*`, `type.*` + composite `type.role.*`, `duration.*`, `easing.*`).
- **`packages/core/src/checks.js`** / **`packages/core/src/index.js`** — contrast-check pairs and the `derivation.require` anchor-suffix check follow the new names (`.solid` instead of `.base`).
- **All five exporters** (`shadcn`, `daisyui`, `echarts`, `bootstrap`, `storybook`) — mapping tables renamed to the grid/ladder/content vocabulary. Bootstrap got the deepest surgery: its private border-subtle mix formula is deleted (now reads the engine-owned `<role>.outline`/`outline-hover` cells directly), its `$light`/`$dark` pseudo-roles read `neutral.tint`/`neutral.text-strong`, and — the part that needed real care — its `hasTypeScale`/`hasSpace` existence-sniffing (`[...map.keys()].some(k => k.startsWith('semantic.type.'))`) was **replaced**, not just renamed. That sniff used to distinguish "user authored a type/space scale" from "nothing exists yet"; now that the engine *always* populates `semantic.type.*`/`semantic.space.*` (as `defaulted` if unauthored), the same existence check would have silently gone true and skipped Bootstrap's `$font-size-base`/`$spacer` emission entirely, since the old code path was `if (!hasTypeScale) { emit our own hardcoded scale }` with nothing in the `else` branch. Bootstrap now always reads from the engine's `type.size.*`/`space.*` slots (provenance-checked for the coverage class instead of existence-checked), so the values it emits are identical but sourced from one place instead of two.
- **Both examples' token files** — `examples/acme/tokens/semantic.tokens.json` and `examples/cathode/tokens/transtyle.bindings.tokens.json` rewritten to author the new anchor names (`primary.solid`, `elevation.{0,1}.surface`, `text.{base,muted}`, `border`). `examples/cathode/tokens/cathode.tokens.json` and `cathode.light.tokens.json` needed no changes (they only define the custom `crt.*` vocabulary, never catalog slot names).
- **`scripts/check-sync.mjs`** — new dead-vocabulary guard: scans `packages/`, `examples/*/tokens`, `examples/*/transtyle.config.json`, and `website/src/docs` for `text-on-`, a bare `.subtle` cell suffix (with a lookbehind excluding the legitimate new `text.subtle` content rung), `surface-raised`, and qualified `semantic.color.<role>.{base,hover,active,contrast}` / `background.base` / `surface.base` / `overlay.base` / `text-muted.base` paths. `website/src/docs/language.md` is the one declared exception (it explains the old→new mapping by name).
- **`scripts/check-grid.mjs`** (new) — compiles Acme directly through `@transtyle/core`, asserts 54 catalog slots exist in both modes, and asserts 5 frozen hex values match the Phase 0 Bootstrap fixture exactly (`primary.tint = #e7effa`, `primary.outline = #b7d2f4`, `primary.on-tint = #005bb6`, `neutral.tint = #edeff1`, `neutral.text-strong = #171b20`) — proving the promoted exporter conventions reproduce the shipped fixture byte-for-byte, not just structurally.
- **Website docs sync** (required by the same commit, per the sync rule): `concepts.md`, `derivation.md`, `language.md` (the biggest rewrite — merged the old "Coming: the role grid" section into the main color-roles/surfaces sections since it's no longer coming, it's here; renamed the section, which meant fixing five `#coming-the-role-grid` anchor references elsewhere), `diagnostics.md`, and all four exporter pages got their mapping tables/examples updated. `roadmap.md`'s "Revised semantic catalog" row moved from Specced to Implemented. Engineering docs (`ir.md`, `derivation.md` status banners) updated from "spec, not yet landed" to "implemented, see check-grid.mjs". A handful of illustrative examples in `docs/specs/cli.md`, `component-layer.md`, `validation-and-coverage.md`, `docs/architecture/plugins.md` also updated for accuracy (outside the guard's mechanical scope, fixed by hand).

## One intentional value change (not a bug)

Value-diffing every file in both examples' `dist/` against pre-migration backups turned up exactly one substantive change, everywhere it appeared: `overlay`/`popover`-family colors (shadcn `--popover`, ECharts `tooltip.backgroundColor`) got slightly more elevated in dark mode (e.g. Acme `oklch(0.26 0.012 255)` → `oklch(0.3 0.012 255)`; light mode unaffected, already clamped at white). Root cause: the old engine aliased `overlay.base` directly to `surface-raised.base` (zero differentiation); the new elevation ladder gives `overlay` its own level (`elevation.3`, one more `raise()` step past the `elevation.2` "raised card" level) — matching what proposal 0001 actually specified (background/surface/surface-raised/overlay as four *distinct* levels) and a more correct design (floating layers sit visually above merely-raised cards). Permitted under ADR-0010 (pre-release, values can change, not just names); documented on the website roadmap page and here.

Everything else — every role's `solid`/`tint`/`outline`/`on-*` hex value, every fixture-verified Bootstrap output, both examples' full color palettes — is byte-for-byte unchanged; only the vocabulary addressing them changed. Verified via a custom value-diff script (extracts every color/number/string token from old vs. new `dist/`, ignoring comments) across both examples' full output tree, and via three representative demo-project builds (React/Tailwind/shadcn, Sass/Bootstrap, Tailwind/daisyUI) to confirm nothing downstream broke.

## Scope decision: `expected/` fixture files left untouched

`examples/acme/expected/bootstrap/*.scss` and `expected/storybook/*.ts` are the Phase 0 hand-written/engine-verified acceptance fixtures. Their *values* still match `dist/` exactly (verified above; Bootstrap doesn't consume the one refined value, `overlay`, at all). Their inline comments still reference pre-revision slot paths (e.g. `// text-on-primary.subtle`) — technically stale, but these files are historical exercise artifacts in the same sense as `docs/exercises/phase0-*.md` (which already carry an ADR-0010 pointer note). Rewriting their comments was in the plan's file list as a nice-to-have ("headers + any slot-name comments") but not required for correctness, and `scripts/check-grid.mjs` is now the live acceptance mechanism going forward. Left as-is; flagged here rather than silently skipped.
