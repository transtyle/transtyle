
## AL1.4 — CSS-variable path

`componentCssBlocks`: selector-scoped `--bs-*` structure blocks for every bound variable with a runtime counterpart (32 + 3 extras), with declaring selectors verified against the partials — three specials found and handled: `nav-underline-*` lives on `.nav-underline`, `$navbar-nav-link-padding-x` writes `--bs-nav-link-padding-x` on `.navbar-nav`, and `--bs-modal-margin`'s responsive re-set is deduped (base wins; the `sm`-up value stays Sass-only, documented). `CSS_EXTRAS` pushes `component.button.padding-*` onto `.btn` directly (they're Sass-chained, so stock-CSS users would otherwise never see authored button padding). `buttonVariantBlocks`: `.btn-<role>`/`.btn-outline-<role>` state colors from grid cells (`solid`/`solid-hover`/`solid-active`/`on-solid`), light + `[data-bs-theme=dark]` — this is the AL1.2 "knobs dropped, results driven" promise delivered; `.btn-light`/`.btn-dark` keep defaults (pseudo-roles have no grid cells; noted in the emitted CSS).

**Stock-page acceptance (verified in-browser, no Sass anywhere):** `bootstrap.min.css` + emitted `bootstrap-theme.css` → `.btn-primary` computes bg `#026fd7` (Acme primary.solid; stock is `#0d6efd`), padding `16px/8px` (component tokens; stock `12px/6px`), radius `8px`, hover/active vars `#005fc6`/`#005bb6` (grid cells); `.btn-outline-danger` text/border `#c92f33` (brand-derived); flipping `data-bs-theme=dark` swaps the hover var to the dark grid value (`#207fe8`).
