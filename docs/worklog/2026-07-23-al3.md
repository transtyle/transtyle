# AL3 — the coverage bar: "ALL tokens mapped", measured and enforced

Per the [first-alpha definition](../../ROADMAP.md) AL3.

## What shipped

- **PrimeNG surface inventory** (`packages/exporter-primeng/tools/extract-surface.mjs` + checked-in `surface-inventory.json`), the twin of AL1.1's Bootstrap one. Source of truth is the real Aura preset object from `@primeuix/themes`: **2759 slots across 98 families** (97 components + the semantic tier), each recording whether Aura supplies the value as a `{token}` reference or a literal — the distinction the classification hinges on.
- **`scripts/check-coverage-bar.mjs`**, wired into `check:all` (now 60 checks), enforcing on **4 examples × 2 targets**: (1) every inventoried slot is accounted for, (2) no `unsupported`/`dropped` row without a note, (3) the PrimeNG inventory hasn't drifted from the installed package.
- **PrimeNG coverage rows** computed from the inventory by a new `src/surface-coverage.js`, shared by the exporter and the checker so they cannot disagree.

## The classification that makes the number honest

Bootstrap's Sass either sets a variable or doesn't. PrimeNG resolves `{token}` references at runtime, so "we don't emit this component" ≠ "this component isn't themed" — most of Aura's component slots point at semantic paths this exporter drives. Three reasons, all reported:

- **driven** (75) — emitted directly.
- **inherited** (1492) — Aura's default references a semantic path we drive, so the component follows the theme without being named. Real coverage.
- **Aura default** (1192) — a literal we don't override, or a reference into a semantic path we don't drive. Honest `unsupported`, always noted.

**The over-claiming near-miss.** The first implementation matched references by prefix: we drive some `formField.*`, so `{form.field.font.size}` counted as inherited. Measuring it showed **221 slots claimed that we demonstrably do not drive** — `formField.fontSize`, `formField.focusRing.*`, `navigation.item.icon.size` among them. Replaced with exact matching (the driven-key set already walks every nested path we emit, so real nesting still matches). Coverage dropped from 1713 to 1492 inherited — the lower number is the true one, and inflating it is precisely what this bar exists to prevent.

## Verifying the bar can fail

A check that cannot fail is decoration, so both failure modes were exercised deliberately:

- Hiding one family (`datatable`) from the PrimeNG rows → `family "datatable" (112 slots) has no coverage row` on all four examples.
- Stripping notes from Bootstrap's drop rows → `105 dropped row(s) with no note — e.g. caret-width` on all four.

Both restored; the bar is green again.

## Side effect worth noting

`STRUCTURAL_RESIDUE` — a hand-maintained array of "components we don't build yet" — is deleted. The inventory measures them now, so that list can never drift from reality. This is the same substitution AL1 made for Bootstrap's blanket "reserved for v2" line.

## Gap this surfaced (not fixed here — measurement was the mandate)

PrimeNG's `semantic.typography.{fontFamily,fontSize,fontWeight,lineHeight}` is **not driven**, even though the IR carries a full type scale (`font.sans`, `type.size.md`, `type.weight.regular`, `type.leading.normal`). It reads as `Aura default` in the report and cascades: every component slot referencing `{typography.font.size}` / `{typography.font.weight}` is counted `Aura default` too. Wiring four semantic values would convert a visible chunk of the 1192 — the single cheapest coverage win now visible, and exactly the kind of thing the bar exists to reveal. Left for its own change because it moves emitted output on all four examples and needs demo re-verification.
