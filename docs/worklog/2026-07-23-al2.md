# AL2 — Component catalog generalization

Per the [first-alpha definition](../../ROADMAP.md) AL2. RFC: [proposal 0003](../proposals/0003-component-catalog-generalization.md).

## The judgment that shaped the pass

The meta-language rule ("two independent exporters needing the identical thing") turned out to be too loose for the component tier: "both libraries have a padding for X" is true of nearly every component, and applying it literally would have rebuilt the N×M matrix [component-layer.md](../specs/component-layer.md) exists to avoid. AL2 sharpened it to **architectural, not nominal, correspondence** — both upstreams must treat the meaning the same _structural_ way. That single distinction is what separated the promotions from the rejections below, and it is now written into the proposal as the standing bar.

## Promoted (4 slots)

- **`component.control.{radius, padding-x, padding-y}`** — verified from source on both sides: Bootstrap's `$btn-padding-y: $input-btn-padding-y !default` (button defaults from a root shared with inputs) and PrimeNG's `buildButton` reading the same `field()` object its inputs read. Two independent upstreams implementing the _same two-level model_, not just both having padding.
- **`semantic.opacity.disabled`** — PrimeNG had `disabledOpacity: '0.6'` hardcoded with the comment "no Transtyle equivalent to derive from"; Bootstrap needs it three times. One slot, deliberately not an opacity ladder.

`button.*` now defaults from `control.*` through a new `component:` form of `defaultFrom` in `COMPONENT_CATALOG`, resolved by an extended component-tier loop in [derive.js](../../packages/core/src/derive.js).

## Rejected, each with a reason (the substance of the pass)

sm/lg size ladder (both have one, rungs disagree — `space.3` vs `space.2`; the disagreement is itself the finding); nav/list item padding (nominal correspondence only); table cell padding (PrimeNG's DataTable is `unsupported` — no second consumer at all); component sizing and icon/asset slots (single-source; assets likely a permanent non-goal); overlay veil strength + mask timing (a real shared near-miss, deferred to its own pass because it interacts with how `scrim` is derived).

Stale `promote:` markers left in the Bootstrap descriptors by AL1.2 were removed for the candidates AL2 rejected — a rejected marker reads as a pending TODO to the next person.

## What changed in output

- **Unauthored systems: byte-identical on both targets.** Promotion reused the rungs both exporters had already independently chosen, which is itself part of the evidence.
- **Bootstrap gains four previously-`unsupported`/chained emissions**: `$btn-padding-{x,y}` (now explicitly the button layer), `$input-border-radius`, `$btn-disabled-opacity`, `$form-check-input-disabled-opacity`.
- **AL1.2's contested call #1 is resolved by the catalog rather than documented away**: Acme authors only `component.button.*`, and its Bootstrap demo now renders buttons at 24px/12px/9999px while form inputs stay at the control defaults (16px/8px/8px). Before AL2, authoring button padding silently moved form fields.
- **AL1's PrimeNG parity gap is closed**: the same authored token set renders `.p-button` at 24px padding with a pill radius — identical to Bootstrap's `.btn-primary`, verified in both live demos, no console errors.

## Guards added

`check:component-tier` now asserts the layering in both directions: an unauthored example resolves `button.*` from `control.*` with `alias(control.*)` provenance, and Acme (which authors only the button layer) must **not** move `control.*`. It also asserts `semantic.opacity.disabled` resolves numeric. `check:all` green at 59.
