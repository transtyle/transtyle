# ADR-0011 — v0 freeze-readiness: IR spec ready, plugin API deferred

**Status:** proposed, 2026-07-22. _Update 2026-07-22 — §2's reconciliation is done:_ [P1](../plan/execution-2026-h2.md) shipped `@transtyle/plugin-kit`, plugins.md was dropped to the interface all eight exporters actually implement, and the drift banner is gone. The plugin API is now accurately specified and executably enforced; **formally freezing it still waits for first publication** (R4, parked), exactly as decided below. Ratified when [R1](../plan/execution-2026-h2.md) (the T11 practitioner sign-off) is signed and Phase 1 formally exits; the freeze _discipline_ it audits for re-arms mechanically at first npm publication ([R4](../plan/execution-2026-h2.md)) per [ADR-0010](0010-pre-release-breaking-changes.md) decision 4.

## Context

The Phase 0 exit criterion listed one unfinished item: _"the formal freeze declaration of IR spec v0 + plugin API v0."_ [ADR-0010](0010-pre-release-breaking-changes.md) (2026-07-20) then changed what "freeze" can mean before release: pre-publication, the catalog may change in place, version numbers do not move, and **"the freeze policy re-arms at first npm publication."** So a literal "declare everything frozen now" is no longer the task — it would contradict ADR-0010's deliberate reservation of the right to make pre-release breaking changes.

What _is_ both possible and valuable now is a **freeze-readiness audit**: verify that every stability guarantee written in [ir.md](../architecture/ir.md), [plugins.md](../architecture/plugins.md), and [versioning.md](../architecture/versioning.md) is either (a) real and mechanically verified today, or (b) explicitly excluded from the coming freeze with a named gate. Doing this before R4 means the re-arm at first publication locks a _known-good, audited_ surface rather than whatever prose happens to exist that day. This ADR is that audit, and its central finding is that the two surfaces are not equally ready.

## Decision

**1. The IR spec v0 content is freeze-ready and will be locked at first publication (R4).** Every guarantee in ir.md is verified against a named ground-truth script that runs in CI:

| IR guarantee (ir.md)                                                                                         | Verified by                                                                                                   | Status                 |
| ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ---------------------- |
| The full role grid (8 roles × grid cells) exists in both modes after DERIVE                                  | `scripts/check-grid.mjs` — asserts 54 catalog slots present in both modes                                     | ✅ real                |
| Elevation ladder (`elevation.0–5.surface`, `1–4.shadow`), content hierarchy, scales                          | `check-grid.mjs` slot enumeration                                                                             | ✅ real                |
| Custom-role archetypes derive the full grid like built-ins                                                   | `check-grid.mjs` (c): Cathode's `crt-amber` derives its full grid                                             | ✅ real                |
| Migration changed vocabulary, not values (except the documented elevation refinement)                        | `check-grid.mjs` (b): frozen spot-check hex vs the Phase 0 Bootstrap fixture, byte-exact                      | ✅ real                |
| **Cross-target value contract: `palette.categorical.1–5` frozen** (shadcn `--chart-1…5` ≡ ECharts `color[]`) | `scripts/check-fixtures.mjs` — fresh Acme `dist/` diffed key-by-key against `examples/acme/expected/`         | ✅ real                |
| Deterministic derivation — identical inputs → byte-identical output                                          | `scripts/check-determinism.mjs` — every example built twice, byte-diffed                                      | ✅ real (4/4 examples) |
| The catalog generalizes past its design inputs                                                               | Radix acceptance test (T9) + GOV.UK & Carbon (T11) compile with **zero catalog amendments, zero diagnostics** | ✅ real                |
| Provenance attached to every resolved value (`authored`/`aliased`/`derived`/`defaulted`)                     | `scripts/check-cli.mjs` — `explain` golden test walks the chain                                               | ✅ real                |

**No IR guarantee failed the audit.** The IR spec is the project's most-tested artifact; it is ready to be the frozen surface at R4.

**2. Plugin API v0 is NOT freeze-ready and is explicitly excluded from the first re-arm.** The audit found the documented plugin contract materially diverges from what the shipped exporters implement — you cannot freeze a contract the implementation does not honor. The specific divergences:

| plugins.md / versioning.md says                                                                             | Reality in `packages/`                                                                                                                    | Gap                                  |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| Exporter interface is `resolve?` + `emit(resolution, ctx)` + `doc?` (three hooks)                           | Exporters export `{ name, emit(normalized, ctx) }` — one hook, receiving the resolved IR, returning `{ files, coverage }`                 | interface shape differs              |
| Bulk of mappings are declarative `mappings/5.x.json` tables _evaluated by core_; coverage derived from them | No `mappings/*.json` exists; mappings are JS arrays inside each `index.js`; coverage is computed by the exporter and returned from `emit` | the declarative layer is unbuilt     |
| Manifest: `"irSpec": ">=0.1 <1"`, `"pluginApi": "^0"`, `targets` as semver ranges                           | `"irSpec": "v0-draft"`, `"pluginApi": "0"`, `targets` as era strings (`"tailwind-v4"`)                                                    | manifest format unspecified/unstable |
| "Core checks declared ranges at load time and refuses mismatches" (versioning.md)                           | Loader validates no manifest field ([audit A8](../audit-2026-07.md))                                                                      | range-checking unimplemented         |
| "The conformance suite is the real plugin spec"                                                             | `@transtyle/plugin-kit` does not exist (it is P1)                                                                                         | the declared "real spec" is unbuilt  |
| `transtyle.lock` + `--frozen` reproducibility                                                               | unimplemented ([audit A4](../audit-2026-07.md))                                                                                           | reproducibility promise unbacked     |

Freezing plugin API v0 now would either freeze a fiction or brand the real, working exporters non-conformant. Instead: **the plugin API freeze is gated on [P1](../plan/execution-2026-h2.md) (the conformance kit)**, which is where the spec and the implementation get reconciled — the kit becomes the executable spec plugins.md already promises it is. Manifest schema + load-time validation ([R3](../plan/execution-2026-h2.md) / audit A8) is a prerequisite of that gate. Plugin API v1 is declared at the Phase 2 exit, per the roadmap, not here.

**3. `report.json` / `config` schemas are freeze-adjacent, gated on R3.** The `$schema` URLs emitted today are fictional (`https://transtyle.dev/schemas/...`, [audit A7](../audit-2026-07.md)). The report/config _shapes_ are stable in practice, but the freeze can only reference real, served schemas — so schema publication (R3) precedes the R4 re-arm.

**4. What the R4 re-arm will lock, precisely.** At first npm publication: the IR spec v0 catalog (§1 above), the cross-target value contract (`palette.categorical.1–5`), the three-tier model, the mode model and polarity rule, and the provenance kinds. From that point ADR-0010's discipline returns in full: additive minors only, nothing removed or re-typed, rule semantics move only via a new rule-pack id. **Not** locked at that point: the plugin API (gated on P1) and `transtyle.lock` (unimplemented).

## Consequences

- **The roadmap's R2, as originally written ("freeze IR spec v0 + plugin API v0" together), is corrected by this audit:** the two surfaces are decoupled. IR spec v0 is freeze-ready now and locks at R4; plugin API v0 freezes later, gated on P1. The [execution ledger](../plan/execution-2026-h2.md) R2 line is annotated to reflect the split; P1's acceptance gains "reconcile plugins.md with the implemented interface" as an explicit deliverable.
- **Honest freeze semantics.** We do not claim a stability guarantee we cannot keep. The IR — the artifact users' token files actually depend on — is the one that is genuinely ready, and that is the one whose readiness this ADR certifies.
- **A pre-publication drift risk is now named.** Because plugins.md describes an aspirational interface, a reader could implement against it and fail. Until P1, plugins.md carries a banner pointing at this ADR: the _implemented_ interface is `emit(normalized, ctx) → { files, coverage }`; the richer contract is the P1 target, not today's reality.
- **This ADR is immutable once ratified** (per the ADR README). Ratification is contingent on R1 (the maintainer's T11 practitioner sign-off); until then it stands as `proposed`. It does not itself move any version number or publish anything — R4 does that.
- **Cost accepted:** deferring the plugin-API freeze means the first third-party exporter pilot (P3) runs against an API that is documented as not-yet-frozen. That is the correct order — better to reconcile the spec with a real external implementer's experience (P3) _before_ freezing than to freeze prose and force-fit reality to it afterward.
